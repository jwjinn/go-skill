# go-tester

테스트 작업을 **로컬 모델에 붙은 별도 `claude` 프로세스**에 넘긴다. 세션에는 결과 JSON 하나만
돌아온다 — 테스트 파일 본문도 실행 로그도 문맥에 들어오지 않는다.

```
세션(상위 모델)                     별도 프로세스(로컬 모델)
  지시서 한 장  ──────────────────▶  읽고 · 쓰고 · 돌리고 · 깨 보고 · 되돌린다
  결과 JSON 하나 ◀──────────────────  {passed, tests_written, control_group, notes}
```

## 기본은 쓰지 않는다

사용자 지시(2026-09-15): 「default 는 로컬 모델을 안 쓰는 거고, go-review 단계에서 로컬 모델을
쓸 거냐고 물어보고 heartbeat 로 통신이 되는지 확인을 하고, 명시적으로 쓴다고 하면 쓴다.」

그래서 켜지는 경로가 **두 번의 명시적 답**을 지난다:

| 시점 | 무엇 |
|---|---|
| 계획을 만들 때 | `/plan` 이 heartbeat 를 돌리고 그 결과를 붙여 「이 계획에 쓰나」를 묻는다 |
| 계획을 돌릴 때 | `/go` 가 heartbeat 를 **다시** 돌리고 계획 때의 답을 보여 주며 재확인한다 |

두 번째 답이 「쓴다」일 때만 `opt-in.json` 이 쓰이고, 그 기록은 **그 계획 파일에 묶인다.**
다음 계획에서는 다시 묻는다 — 옵트인이 조용히 이어지면 「기본은 안 씀」이 거짓이 되기 때문이다.

묻지 않고 지나간 경로는 **안 쓰는 쪽으로** 닫힌다. `tester.sh` 는 옵트인 없이 rc 70 을 내고
프록시조차 띄우지 않는다.

## control_group 이 산출 계약의 본체다

`tests_written` 에 「이 테스트가 X 를 잠근다」를 적으면, 그 X 를 **일부러 깨서 테스트가 붉어지는
것을 관측**해야 한다. 관측하지 않았으면 `went_red` 는 `false` 이고, 그러면 `mode=full` 산출은
`rc 67` 로 거부된다.

보호를 지웠을 때 실패하지 않는 테스트는 무엇을 지키는지 알 수 없다. 통과하는 이유가 보호
때문인지 우연인지 아무도 모르고, 그런 테스트가 쌓이면 초록은 「돌았다」가 아니라 「실패하지
않았다」가 된다.

대조군은 모델이 아니라 `controlgroup.sh` 가 돌린다 — **격리된 워크트리**에서 깨고 워크트리째
버린다. 모델에게 git 조작을 맡기면 `git stash` 를 쓰고, 공유 스택에서 그것은 남의 작업을 삼킨다.

## 거부하는 것

| rc | 무엇 |
|---|---|
| 66 | 테스트 파일 밖을 고쳤다 — 테스트를 통과시키려 소스를 고치는 경로를 종료코드로 막는다 |
| 67 | 대조군이 0건 |
| 68 | **부모의 계획·리뷰 파일을 고쳤다** — 원본을 복원하고 거부한다 |
| 70 | 쓸 수 없다(꺼짐·옵트인 없음·heartbeat 불가) |

68 이 있는 이유는 실측이다. `--setting-sources ""` 를 빼면 부모의 go-review Stop 훅이 자식에
걸리고, 걸린 자식은 **부모의 계획 파일을 편집해서 빠져나간다**(재현 1/1 — 미완료 체크박스 2개를
지웠다). 통제는 세 겹이다: 플래그 · 환경변수 우회 · 해시 대조. 앞의 둘이 조용히 깨졌을 때
그것을 알아차릴 방법이 세 번째다.

## 판정은 존재가 아니라 호출

`probe.sh` 는 `command -v` 를 쓰지 않는다. 프록시를 띄우고 실제로 한 번 부른 뒤 내린다.

근거는 같은 레포군의 사고다. go-review 의 codex 폴백이 `shutil.which("codex")` 만 봐서,
codex 가 **설치돼 있는데 못 도는** 조건에서 전 자리를 codex 로 둔 채 진행했고 리뷰가 0회였다.
아무 신호도 없었다. 존재는 가용성이 아니다.

## 쓰기

```bash
TT=~/.claude/skills/go-tester

python3 "$TT/tester/_config.py"            # 켤 수 있나 · 어느 구성 파일을 읽었나
bash "$TT/tester/probe.sh" --for-plan      # heartbeat 한 줄
bash "$TT/tester/tester.sh" --task task.txt --mode full --gate 'go test ./... -count=1'
bash "$TT/tester/tester.test.sh"           # 대조군 21검사
bash "$TT/scripts/rollback.sh"             # 되돌릴 계획(기본 dry-run)
```

프로젝트 설정 `.claude/tester/config.json`:

```json
{ "endpoint": "http://<호스트>:<포트>/v1", "model": "<모델 이름>", "max_concurrency": 4 }
```

키는 여기 적지 않는다. `~/.config/go-skill/tester.env` 의 `GO_TESTER_API_KEY` 하나만 읽는다(600).

## 의존

| 도구 | 구분 | 없으면 |
|---|---|---|
| `python3` · `git` · `curl` | 필수 | 구성 해석 · 대조군 워크트리 · heartbeat |
| `uvx` | 필수 | 변환 프록시를 띄우지 못한다(`brew install uv`) |
| `claude` | 필수 | 자식 프로세스 자체 |
| `lsof` | 선택 | 프록시 회수가 pid 파일에만 의존하게 된다 |

## 되돌리기

`ROLLBACK.md` 에 도입 직전 좌표가 있고 `scripts/rollback.sh` 가 그것을 읽는다. 세 층이다:
설정 한 줄(옵트인 삭제) · 심링크 복원 · 태그 기준 revert. 성능이 안 나올 때 첫 대응은 1층이고
코드는 건드리지 않는다.
