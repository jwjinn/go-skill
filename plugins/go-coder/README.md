# go-coder — 구현을 로컬 모델에 위임한다

`go-tester` 의 형제다. 그쪽은 **테스트**를 넘기고 이쪽은 **구현**을 넘긴다.
통제 철학은 같고 **대조군의 방향이 반대**다.

| | go-tester | go-coder |
|---|---|---|
| 넘기는 것 | 테스트 파일 | 구현 코드 |
| 대조군 | 보호를 지우면 **붉어지나** | 착수 전에 그 테스트가 **붉었나** |
| 쓰기 범위 | `test_path_patterns` | 계획 항목이 선언한 **대상 파일** |
| 호출 경로 | `claude` + LiteLLM 프록시 | **`codex -p <프로파일>`** |
| 원장 | `tester.jsonl` | `coder.jsonl` |

## 왜 codex 인가

이 위임의 근거가 된 벤치마크(2026-09-16 · 과제 7 · 실행 68회)가 **codex 경로에서** 측정됐다.
특히 `model_catalog_json` 주입이 350행 파일의 부분 수정을 3회 중 1회에서 3회 전부로 바꿨는데,
그것은 codex 고유 설정이라 다른 경로에서 재현되지 않는다. 측정한 경로와 쓰는 경로가 같아야
그 수치를 이 도구의 기대값으로 삼을 수 있다.

## 언제 쓰나 — 격자가 정한다

`go-review:plan` §6-b 2단계의 격자가 판정한다. **「로컬 구현」 갈래일 때만** 이 도구를 부른다.

| 명세 | 테스트 | 되돌리기 | 규모 | 판정 |
|---|---|---|---|---|
| 없음 | — | — | — | 명세부터 (어느 모델도 아니다) |
| 있음 | 없음 | — | — | 테스트부터 |
| 있음 | 있음 | 쉬움 | 파일 1~2 | **로컬 구현 ← 여기** |
| 있음 | 있음 | 쉬움 | 여러 파일 | 미측정 (세션 모델) |
| 있음 | 있음 | 어려움 | — | 세션 모델 |

## 쓰는 법

```bash
bash coder/coder.sh \
  --task <지시서 파일> \
  --targets 'path/to/file.py' \
  --gate 'python3 -m pytest -q' \
  --cwd <레포> --out <결과.json> --label <원장 이름>
```

`--targets` 와 `--gate` 는 **필수**다. 전자를 비우면 쓰기 범위 통제가 꺼지고,
후자가 없으면 착수 전과 후를 가를 수 없다.

## 종료 코드

| rc | 뜻 |
|---|---|
| 0 | 대상 파일만 바뀌었고 게이트가 초록이다 |
| 64 | 사용법 오류(대상·게이트 누락 · 절대경로 대상) |
| 65 | 자식이 아무 출력도 내지 않았다(codex 자체가 실패) |
| 66 | 대상 파일 **밖**을 고쳤다 — 자식이 새로 더럽힌 것만 되돌렸다 |
| 67 | 착수 전 게이트가 **이미 초록**이다 |
| 68 | 부모의 **계획 파일**을 건드렸다(복원했다). ⛔ 통제가 깨진 것이니 사람에게 말해라 |
| 69 | 완료 후 게이트가 **붉다** — 산출은 그대로 두었다 |
| 70 | 설계된 **폴백**(안 켜짐·codex 없음·프로파일 없음·파일 수 상한 초과) |

⚠ **rc 70 은 실패가 아니다.** 그때는 세션이 직접 구현하고 사유를 종료 보고에 남긴다.

⭐ **rc 67 이 이 도구의 핵심이다.** 고칠 것이 없는 상태에서 시작하면 「고쳤다」를 판정할
방법이 없다. 테스트를 먼저 쓰고 그것이 붉은 것을 확인한 뒤에 불러라.

## 켜는 법 — 기본은 안 쓴다

```json
// <레포>/.claude/coder/config.json
{ "enabled": "ask", "profile": "fabrix-qwen" }
```

`enabled` 기본은 `ask` 이고, 옵트인(`.claude/coder/opt-in.json`)이 없으면 호출이 0회다.
⚠ 옵트인은 **go-tester 와 따로** 받는다. 구현 위임은 테스트 위임보다 큰 결정이고,
한 번의 「쓴다」로 둘이 같이 켜지면 사람이 무엇에 답했는지 모르게 된다.

⛔ `profile` 을 비워 두면 호출하지 않는다. 없는 프로파일로 codex 를 부르면 base config 로
조용히 돌아 **상용 모델에 청구된다** — 조용한 실패 중 가장 비싼 부류다.

## 떼는 법 — 세 층이고, **1층이 어디서나 듣는다**

성능이 나쁘면 빼기 쉬워야 한다는 것이 이 도구를 형제로 만든 이유다(사용자 결정 2026-09-16).

**① 구성으로 끈다 — 권장.** 즉시 듣고 되돌리기 쉽다.

```json
// <레포>/.claude/coder/config.json
{ "enabled": "off" }
```

그러면 `_config.py` 가 `CODER_ENABLED=0` 을 내고 `coder.sh` 는 codex 를 부르지도 않는다(rc 70).
`plan.md` 의 격자는 「로컬 구현」 갈래를 내지 않고 그 항목은 「세션 모델」로 간다.
⭐ **아무것도 안 해도 이미 꺼져 있다** — `profile` 기본값이 비어 있어 판정이 `no_profile` 이다.

**② 심링크를 지운다 — 다른 레포에서 쓸 때.**

```bash
rm ~/.claude/skills/go-coder
```

⚠⚠ **이것만으로는 go-skill 레포 안에서 떼지지 않는다**(2026-09-16 실측). `_plugins.sh` 는
`CLAUDE_PLUGIN_ROOT` 가 없으면 **자기 위치**에서 형제를 찾고, 그러면 `plugins/go-coder/` 가
심링크와 무관하게 보인다. 그것은 설계대로다 — 개발본이 정본이어야 한다.
⇒ 심링크 제거가 듣는 것은 **이 저장소 밖에서 쓰는 조건**이다(실측: 마켓플레이스 모양의
`CLAUDE_PLUGIN_ROOT` 를 주면 rc 1 로 못 찾는다).

**③ 디렉토리를 지운다 — 완전 제거.** `plugins/go-coder/` 를 지우고 `plan.md` 의 격자에서
「로컬 구현」 행을 뺀다. 되돌리기 어려우므로 ①로 충분한지 먼저 보라.

## 실물에서 배운 것 (2026-09-16 첫 시험)

**① `--output-schema` 를 쓰면 안 된다.** 주면 작은 모델이 「구조화 출력을 내는 것」을 과업으로
읽고 **도구를 한 번도 쓰지 않은 채** 스키마를 채워 끝낸다. 실측 2/2 — 토큰 2,830 · 한 턴 ·
파일 무변경인데 `files_changed:["slug.py"]` 와 `notes:"고칠 파일이 있는지 먼저 확인 중"` 을 냈다.

⭐ go-tester 는 **반대 방향으로** 같은 뿌리를 밟았다(다중 턴 뒤 구조화 출력으로 전환하지 못해
다 해 놓고 rc 65 로 버려졌다). 뿌리는 하나다 — **구조화 출력 강제와 도구 사용이 충돌한다.**
여기서는 판정이 자식의 JSON 에 의존하지 않으므로(게이트와 git 으로 부모가 직접 잰다) 스키마를
포기하는 쪽이 옳았다. JSON 은 원장용 부가 정보이고, 못 읽으면 `rounds: -1`(모른다)로 남긴다.

**② 실패했을 때 로그를 남기지 않으면 진단할 수 없다.** 첫 실행이 rc 69 였는데 `trap rm -rf`
가 자식 로그를 먼저 지워 **왜인지 알 방법이 없었다.** 지금은 실패 시 `<out>.child.log` 와
`<out>.prompt.md` 를 남긴다.

**③ 소요 시간이 「일을 했나」를 드러낸다.** 실패한 두 회차는 4~6초였고 성공한 회차는 23초였다.
원장에 `elapsed_sec` 을 남기는 이유가 이것이다.

## 대조군

```bash
bash coder/coder.test.sh     # 검사 수는 실행 출력의 마지막 줄이 정본이다
```

⚠ codex 는 **스텁**이다. 여기서 재는 것은 「모델이 잘 고치나」가 아니라 **「우리 통제가 도는가」**다.
실물에서 새 거부 사유가 나오면 **스텁에 먼저 넣어라.**

⭐ 이 스위트가 만드는 중에 결함 하나를 잡았다 — `python3 … || printf '0'` 이 파이썬의 실패를
삼켜 스키마 위반이 조용히 통과했다(판정을 `||` 뒤에서 읽은 것). 그리고 가장 위험한 자리는
**부모의 미커밋 작업을 지우는 것**이라 그 대조군(⑤-b)을 따로 두었다.
