⚠ **아직 구현하지 마라.** 이 명령의 산출물은 계획이고, 승인은 내가 `/go` 로 한다.
조사·측정을 위한 읽기와 라이브 조회는 해라(그게 이 단계의 본체다).

⚠⚠ **계획 파일(`.claude/plan-active.md`)을 이 단계에서 만들지 마라.** 그 파일은 Stop 훅이

시작된다**. 계획 파일은 `/go` 로 승인받은 뒤에 쓰는 것이다.

## 1. 실측 먼저 — 짐작으로 계획을 세우지 마라

계획의 전제가 되는 사실을 **직접 확인**해라. 실무에서 계획이 틀렸던 이유는 거의 항상
"재지 않고 짐작한 것"이었다(커버리지 50.7% 오진 → 실제 87.1% · "이미지를 못 받는다" →
클러스터가 4일째 그 이미지를 돌리고 있었다).

- 라이브가 있으면 **라이브부터** 봐라. 코드·문서보다 우선이다.
- ⭐ **0 이나 낮은 수가 나오면 탐지기부터 의심해라.** 데이터 부재인지 도구 부재인지 가른 뒤에
  결론을 내라. 필요하면 대조군(정상이면 잡히는 것)을 먼저 돌려 탐지기 생존을 증명해라.
- 못 잰 것은 **못 쟀다고 써라.** 계획에 "미측정" 이라 적힌 항목과 "없음" 은 다른 말이다.

### ⛔⛔ 앞 초안에서 **숫자를 옮길 때 다시 재라** (2026-09-15 실측)

초안을 개정하거나 이전 라운드 문서에서 수치를 가져올 때, 그 숫자가 **그때는 맞았고 지금은
틀린** 경우가 있다. 실측: 한 계획이 목업 대응표 행수를 셋 적었는데 **전부 틀렸다**
(85→실제 111 · 138→169 · 117→133). 이전 라운드의 표를 검증 없이 옮긴 것이었다.

그 숫자가 워커 지시서로 내려가자 **워커 셋이 각자 「내가 본 것과 다르다」로 멈췄다.**

⇒ **규칙 둘**:
1. **완료 조건에 숫자를 쓰지 마라.** 「대응표 117행 보류 0」이 아니라 **「그 파일의 보류 0」**이다.
   숫자는 파일이 자라면 틀리고, 틀린 숫자는 작업자를 멈추게 한다.
2. 꼭 숫자를 적어야 하면 **그 자리에서 세어 명령과 함께 적어라**
   (`wc -l <경로>` → `133행(2026-09-15 실측)`).

⚠ **한 자리만 보고 「없다」고 확정하지 마라.** 같은 차수에 그 반대도 겪었다 — 공용 대응표
디렉토리만 보고 「그 화면 목업은 없다」고 워커에게 **확정 진술**했는데, 전수 검색하니 있었다
(목업들이 각자 자기 디렉토리에 대응표를 갖는 구조였다). 「없다」는 「있다」보다 **넓게 재야**
말할 수 있는 주장이다.

## 2. 이미 있는 것을 먼저 찾아라

원 레포는 **있는 걸 다시 만드는 실패**를 반복했다(정본 카탈로그가 있는데 프론트가 경쟁 분류를
새로 만듦 · 알림 진입점이 이미 배선돼 있었음).

- 화면이면 `docs/UIUX/관제화면-기능카탈로그.md` 를 먼저 읽어라(화면 156·공유 부품 99).
- 라우트·API 는 `authz` 선언표와 대조해라 — **"화면이 있다" 가 "데이터가 있다" 는 뜻이 아니다**
  (mock 전용 화면이 실재한다).
- 같은 사실이 두 곳에 담기게 되는 설계인지 확인해라. 그렇다면 정본을 하나로 정하는 것이 먼저다.

## 3. 계획에 반드시 담을 것

- **결정과 근거** — 고른 안 + 기각한 안 + 왜. 근거는 위 실측을 인용해라.
- **범위 밖** — 무엇을 안 하는지와 그 이유. 안 적으면 나중에 조용히 새어 들어온다.
- **위험 하나** — 특히 **fail-open 방향**(빠뜨리면 열리는 설계)인지. 그렇다면 그것을 막는
  계약 테스트가 계획의 본체다.
- **검증 방법** — 무엇을 어떻게 확인하면 "됐다" 인가. 테스트를 넣는다면 **대조군**(그 보호를
  지웠을 때 실제로 실패하는지)까지가 한 항목이다. 대조군 없는 테스트는 근거가 아니다.
  ⭐ 항목마다 **위임 여부를 세 갈래로** 적어라 — `위임 가능 (full)` / `일부 위임 (테스트 부분만)` /
  `위임 불가 — 사유`. 판정 기준과 표 형식은 §6-b 의 Q-T 에 있고, **승인을 받은 뒤에** 적는다.
  이 표기가 없으면 실행 단계에서 매번 다시 판단하게 된다(실측 — 사용자가 「도대체 언제
  부른다는 건지 모호하다」고 지적해서야 드러났다).
- **단계와 항목** — `/go` 로 바로 승인할 수 있게 단계별로 번호를 매겨라(P0·P1… 또는 1·2…).
  각 항목은 한 줄로 무엇을 하는지 알 수 있어야 한다.
- **선행 조건** — "이걸 안 하면 이 설계가 성립하지 않는다" 는 항목을 표시해라.
- **병렬 배치** — ⭐ 요구사항을 분석하는 **이 단계에서** 무엇을 병렬 에이전트로 보낼지 정한다
  (사용자 지시 2026-09-13: 「요구조건을 받고 무엇을 병렬 에이전트로 하는지를 정하고 그대로 할
  수 있게 … 플랜에 무엇을 병렬로 할지를 이미 다 정해두는 거야」). 항목마다 건드릴 파일을
  **grep 으로 실측**해 적고, 교집합 0 인 것끼리 워커로 묶고, 앞 결과에 의존하는 것은 다음 파도로
  보낸다. 표 형식은 §6-c. 병렬로 갈 이유가 없으면 「단독 — <이유>」 한 줄 — **그것도 판정이다**
  (안 적은 것과 다르다).

## 4. 물어야 할 것만 물어라

- **되돌릴 수 없는 것**(데이터 삭제·외부 반영·머지·비용)만 골라 **AskUserQuestion 으로 한 번에**.
- 조사하면 알 수 있는 것은 묻지 말고 조사해라.
- 설계 갈림길이 진짜로 있으면(어느 쪽도 합리적이고 결과가 크게 다르면) 그것도 물어라.
  다만 권고안을 먼저 말하고 물어라 — 선택지만 나열하지 마라.

## 5. 그 프로젝트에 이미 절차가 있으면 그것을 따라라

⭐ **먼저 `CLAUDE.md`·`AGENTS.md`(있으면 그 디렉토리의 것까지)를 읽어라.** 그 프로젝트가
이미 정한 순서가 있으면 새로 만들지 말고 그것을 계획에 넣는다 — 계획이 규약과 어긋나면
구현이 아니라 리뷰에서 막힌다.

자주 있는 부류:

- **UI 변경**: 디자인 토대 문서 → 구현 → 렌더 감사(실제 화면을 보는 단계) 순서가 있는지
- **인프라 변경**: 라이브 상태와 선언(매니페스트)을 **대조**하고 계획해라 — 어느 방향이든
  apply 가 조용히 덮어쓴다(둘이 갈라지는 것은 어느 레포에서나 반복되는 함정이다)
- **요구 접수**: 원문 독해 → 현 코드 실측 → 설계 확정 → 추적표 순서가 정해져 있는지

## 6. ⭐ 마지막에 **초안 파일**을 남겨라 — `/go` 가 이것을 요구한다

계획을 말로만 제시하면 `/go` 는 **네 기억에 의존**하게 되고, 세션이 끊기거나 문맥이 밀리면
승인된 것이 무엇이었는지 아무도 모른다. 그래서 계획은 파일로 남는다.

`.claude/plan-draft.md` 에 아래를 써라(⚠ `plan-active.md` 가 **아니다** — 그건 Stop 훅이 읽는
파일이라 승인 전에 만들면 착수가 강제된다):

```markdown
# <제목> (<날짜>)

## 목표 계약
원 요청: "<사용자가 처음 말한 것 **그대로 인용**. 네 요약으로 바꾸지 마라>"
수용 기준:
  - <관측 가능한 조건. "잘 된다" ✗ / "빈 배열 입력에 500 대신 200+빈 목록" ✓>
범위 밖: <안 하기로 한 것과 이유>

## P0 — <단계 이름>
- [ ] P0-1 …

## 병렬 배치 (go-fanout · 병렬이 아니면 「단독 — <이유>」 한 줄)
| 파도 | 워커 | 항목 | 파일 집합(실측) | 공유 자원 |
|---|---|---|---|---|
| W1 | A | P1 · P2 | `backend/x/**` · `web/src/y.ts` | 도커 빌드 |
| W1 | B | P3 | `infra/z.yaml` | 그림자 배포 |
교차 검사: 워커별 `git diff --name-only <base> <head>` 를 합쳐 `sort | uniq -d` → **빈 출력**
파도 끝(코디네이터): 교차 0 → PR 머지 → 배포·검증 → 원장 합치기 → **worker-release + cleanup.sh --apply** → 추적표

## C — 자원 회수
- [ ] C1 파도 끝마다 그 파도 워커의 `worker-release` · `worker-list` 로 잔존 0 확인
- [ ] C2 마지막에 `cleanup.sh --run <run_id> --apply` · 아카이브 생성 확인 · 워크트리 0
```

- **원 요청은 인용이다.** 여기서 요약하면 드리프트의 출발점이 그 문장이 된다.
- 단계·항목을 그대로 체크박스로 적어라 — `/go` 가 이 파일을 **그대로** `plan-active.md` 로 옮긴다.
- 초안은 승인 전이므로 어떤 게이트도 보지 않는다. 마음껏 고쳐 써라.

### 6-b. ⭐ 초안에 **`## 결정 필요(승인 전)`** 절을 반드시 넣어라 — `/go` 가 이것부터 본다

사용자 지시(2026-09-03): 「플랜을 보고 질문을 해야 한다, 혹은 사용자가 목업처럼 선택을 해야 한다면
go 를 돌릴 때 **먼저 다 정하고** 돌릴 수 있게」. `/go` 는 이 절에 열린 항목이 있으면 **착수하지 않고**
먼저 닫는다(go.md §0-c). 그래서 계획 단계에서 **사용자에게 물을 것을 전부 여기로 모아라.**

세 부류로, 각 항목에 **권고**와 **닫힘 조건**을 붙인다:

```markdown
## 결정 필요(승인 전)
- [ ] Q1 [선택] 화면 ① 목업 A~D 중 어느 안인가 — 권고: B · 닫힘: index.html 에 ✅ + P2 를 그 안으로 재작성
- [ ] Q2 [질문] main PR 머지를 /go 가 하나, 사람이 하나 — 권고: 사람 · 닫힘: 답 1개
- [ ] Q3 [선행 산출물] 목업 4화면 × 4안(모든 클릭에 다음 화면) — 닫힘: _check.mjs 죽은 클릭 0 · 사용자에게 제시
```
(표 형식도 된다 — 마지막 열이 `열림`/`⏳` 이면 열린 것, `닫힘`/`✅` 이면 닫힌 것으로 센다.)

- **[질문]** 되돌릴 수 없는 결정·비용·외부 반영(배포·머지·발송) 주체·범위 포함 여부. 조사로 알 수 있는
  것은 넣지 마라 — 조사해라.
- **[선택]** 안이 둘 이상이고 결과가 크게 다른 것. 권고를 반드시 붙여라(선택지만 나열하지 마라).
- **[선행 산출물]** 고르려면 먼저 만들어 봐야 하는 것(목업·비교표·시연). 이것은 `/go` **앞에서** 만든다 —
  계획 안에 넣으면 그 자리에서 사용자를 기다리게 된다.
- 물을 것이 **없으면** 절을 만들고 `없음 — <왜 없는지 한 줄>` 이라 적어라. 절이 없으면 `/go` 가
  「안 적었다」와 「없다」를 가르지 못해 초안을 스캔하라고 되돌린다.
- ⚠ 계획 본문의 체크박스에 「사용자 확인 후」·「선택 뒤」 같은 대기를 심지 마라 — 그것은 이 절의 항목이다.

#### ⭐⭐ Q-T — 테스트 위임: **승인을 먼저 받고, 그 다음 어디에 위임할지 계획에 넣는다**

사용자 지시(2026-09-15): 「default 는 로컬 모델을 안 쓰는 거고, go-review 단계에서 로컬 모델을
쓸 거냐고 물어보고 **heartbeat 로 통신이 되는지 확인**을 하고, 명시적으로 쓴다고 하면 쓴다.」

같은 날 두 번 보강됐다. 「사용할거면 **endpoint 및 api 키를 응답**을 해라」 · 「로컬 모델을
사용하겠다는 **명시적 승인을 먼저 받고 나서**, 플랜을 사용할 때 **어느 곳에 위임을 할 것인지에
대해서 플랜에 넣는** 식으로」.

⇒ **순서가 규약의 본체다.** 아래 셋을 그 차례로 한다. 뒤엣것을 앞에 하면 「쓸지도 모르는데
미리 표기한다」가 되고, 앞엣것만 하면 「쓴다고 했는데 어디서 쓰는지 모른다」가 된다.

##### 1단계 — 승인을 받는다 (넷을 함께 보여라)

```bash
# ⭐ 설치 위치는 **찾는다** — 고정 경로를 적지 마라(2026-09-16).
#   심링크 설치는 `~/.claude/skills/go-tester`, 마켓플레이스 설치는
#   `~/.claude/plugins/cache/<마켓>/go-tester/<버전>` 이다. 고정 문자열을 적으면 후자에서
#   「go-tester 없음」으로 읽혀 위임이 조용히 rc 70 으로 닫힌다 — 켰다고 믿는데 안 쓴다.
TT=$(bash "${CLAUDE_PLUGIN_ROOT}/hooks/_plugins.sh" go-tester tester/_config.py) || TT=""
python3 "$TT/tester/_config.py" | grep -E '^TESTER_(ENABLED|MODE|ENDPOINT|MODEL)='
bash "$TT/tester/probe.sh" --for-plan     # heartbeat + 엔드포인트가 한 줄로 나온다
ls -l ~/.config/go-skill/tester.env 2>/dev/null && echo "키 파일 있음" || echo "키 파일 없음"
```

**① 엔드포인트와 모델** — `probe.sh --for-plan` 이 한 줄에 같이 낸다.
**② 키 상태** — ⛔ **키 값을 출력하지 마라.** 「있다·없다·권한」만 말한다. 값을 화면에 내면
그것이 대화 기록·전사에 남는다. 키는 `~/.config/go-skill/tester.env` 한 자리에만 산다(권한 600).
**③ 이 계획의 위임 대상 수** — 2단계를 **미리 한 번 돌려** 개수만 보여 준다(이름은 3단계에서).
**④ 안내 한 줄** — 「쓴다고 답하면 그 항목에 닿을 때만 부르고, 그 밖에는 세션이 직접 쓴다」.

```markdown
- [ ] Q-T [질문] 테스트 에이전트(로컬 모델) 사용
      · heartbeat OK 744ms — qwen3-coder-next @ http://…:30801/v1
      · 키: `~/.config/go-skill/tester.env` 에 있음(권한 600). 값은 여기 적지 않는다
      · 이 계획의 위임 대상 **15개**(통째 6 · 테스트 부분만 9) — 전체 104 항목 중
      · 쓴다고 답하면 **그 항목에 닿을 때만** 부른다. 그 밖에는 세션이 직접 쓴다
      · 권고: 쓴다 · 닫힘: 답 1개 + 3단계 표기 완료
```

- heartbeat 가 **불가**면 선택지는 「안 쓴다」뿐이다. 사유를 보여 주고 닫은 채로 넣어라.
- 키 파일이 **없으면** 그것도 닫힌 항목이다(엔드포인트가 살아 있어도 인증이 안 된다).
  ⚠ 2026-09-15 에 **만료된 키**를 「가드가 차단한다」로 오진했다. 403 이 나오면 키부터 확인해라.
- 구성이 `on`·`off` 로 **명시**된 프로젝트에서는 이 항목을 넣지 마라(사람이 이미 정했다).
- go-tester 가 설치돼 있지 않으면 항목 자체가 없다(그것이 정상이다).
- ⚠ 이 질문을 「테스트는 나중에 정한다」로 미루지 마라 — 그러면 `/go` 착수 뒤에 묻게 되고
  그 자리가 곧 사용자 정지다.

##### 2단계 — 항목마다 판정한다 (세 갈래)

조건 셋을 **전부** 만족해야 통째로 넘길 수 있다.

| 조건 | 무슨 뜻인가 |
|---|---|
| 산출물이 **테스트 파일**이다 | 구현 코드·문서·매니페스트·스크립트는 해당하지 않는다 |
| **게이트 명령**으로 통과 여부가 판정된다 | 사람이 눈으로 봐야 하는 것은 해당하지 않는다 |
| **대조군**을 만들 수 있다 | 보호를 지웠을 때 붉어지는 것을 보일 수 있어야 한다 |

그 결과가 셋 중 하나다.

| 갈래 | 언제 | 무엇을 넘기나 |
|---|---|---|
| **위임 가능 (full)** | 셋을 다 만족한다 | 항목 전부 |
| **일부 위임 (테스트 부분만)** | 구현이 본체인데 테스트가 딸려 있다 | **테스트 부분만.** 무엇을 넘기는지 항목에 적어라 |
| **위임 불가** | 하나라도 어긋난다 | 넘기지 않는다. 사유를 적어라 |

⭐⭐ **「일부 위임」을 빠뜨리지 마라 — 실전에서 이것이 가장 많다.** 실측(2026-09-15 · 104항목):
통째 **6**건, 테스트 부분만 **9**건, 나머지 불가였다. 2분류만 쓰면 그 9건이 전부 「불가」로
떨어져 위임할 수 있는 양이 **절반 이하**가 된다.

⭐ **게이트 실행(`run` 모드)은 표기하지 않아도 된다.** 산출물이 테스트 파일이 아닌데도 넘길 수
있는데(파일을 만들지 않으므로 첫 조건이 적용되지 않는다), 워커가 자기 게이트를 돌리는 것은
어차피 매 단계 일어나므로 그 자리에서 정해도 늦지 않다.

**모드**는 무엇을 넘기느냐가 정한다: 쓰기만 `write` · 실행만 `run` · 쓰고 돌리고 대조군까지 `full`.

##### 3단계 — 표기를 계획에 넣는다 (이것이 닫힘 조건이다)

**항목 줄 끝에** 한 줄로 덧붙인다. ⚠ 본문을 다시 쓰지 마라 — 거기에 실측 근거와 기각 이유가
들어 있고, 다시 쓰면 요약되며 사라진다.

```markdown
- [ ] P4-3 EmptyState.test.tsx — 5 사유 각각 렌더 + 타입 대조군(@ts-expect-error 픽스처)
      · **위임 가능 (full)** — 순수 테스트 + 타입 대조군이다

- [ ] P1-3 iam/useradmin.go — roleRank 에 developer · useradmin_test.go 갱신 · 계약 테스트 행 추가
      · **일부 위임 (full · 테스트 부분만)** — 구현이 본체다. `useradmin_test.go` 갱신과
        계약 테스트의 developer 행만 넘긴다
```

그리고 **요약 표**를 초안에 한 번 둔다. 실행 세션이 이것만 보고 대상을 셀 수 있어야 한다.

```markdown
### 테스트 위임 대상

| 구분 | 수 | 항목 |
|---|---|---|
| 위임 가능 (full) | 6 | P1-2 · P2-2 · P3-2 · P4-3 · P6-3 · P12-4 |
| 일부 위임 (테스트 부분만) | 9 | P1-3 · P1-6 · P3-4 · P3-5 · P6-4 · P9-1 · P10-1 · P10-2 · P11-1 |
| 위임 불가 | 나머지 | 스크립트 신설 · 문서 · 라이브 조회 · 브라우저 렌더 · 리뷰 |
```

⚠⚠ **1단계의 답이 「안 쓴다」면 2·3단계를 하지 마라.** 쓰지 않을 표기를 다는 것은 소음이고,
다음 사람이 「켜져 있나 보다」로 읽는다. 대신 `테스트 에이전트: 미사용(<사유>)` 한 줄만 남긴다.

### 6-c. ⭐ 초안에 **`## 병렬 배치`** 절을 넣어라 — 무엇을 병렬로 할지는 여기서 정한다

사용자 지시(2026-09-13): 「go 스킬을 활용한 플랜을 사용할 때, 요구조건을 받고 무엇을 병렬 에이전트로
하는지를 정하고 그대로 할 수 있게 프로세스를 가져가자. 그리고 종료가 되면 자원을 회수하는 것도
포함해서. 저 플랜에 무엇을 병렬로 할지를 이미 다 정해두는 거야.」

**왜 계획 단계인가.** 실행 중에 「이건 워커로 보내자」를 정하면 파일 집합 교차를 그때 재게 되고,
그 순간 이미 두 워커가 같은 파일을 만지고 있다. 이 레포가 여섯 번 밟은 「병렬 세션 충돌」이 전부
그 형태였다. 교차는 **코드를 열기 전에** 재야 0 으로 만들 수 있다.

**어떻게 정하나** — 항목마다 셋을 적는다:

1. **파일 집합(실측)** — `grep -rln <핸들러명·타입명·라우트>` 로 건드릴 파일을 세어 적는다.
   짐작으로 적은 집합은 교차 검사를 통과하고도 실제로 겹친다(2026-09-13 W3: 기동 배선 두 파일
   `main.go`·`server.go` 가 세 워커에 다 걸렸다 — 미리 알았기에 「최소 발자국 한두 줄」로 허용했다).
2. **의존** — 앞 항목의 산출물(신설 패키지·API·문서)을 읽어야 하면 **다음 파도**다. 같은 파도에
   넣으면 뒤 워커가 없는 것을 참조하거나 자기가 다시 만든다.
3. **공유 자원** — 도커 데몬 · 그림자 스택 · 클러스터 · Harbor. 두 워커가 같은 것을 동시에 쓰면
   한쪽이 죽는다(colima 2GiB 로 빌드 4개 → 사망 · 워커 셋 연달아 기동 → setup 셋 다 실패).
   공유 자원을 쓰는 항목은 **코디네이터 몫**으로 빼거나 한 파도에 하나만 둔다.

**자원 회수는 계획의 항목이다.** `## C — 자원 회수` 두 줄이 체크박스이므로 완주 게이트가 센다 —
「나중에 정리하자」가 밤새 살아 있는 터미널 15개·워크트리 13개가 됐다(2026-09-13 실측). 회수는
**파도 끝마다**(C1)이고 맨 끝 cleanup(C2)은 두 번째 패스다. ⚠ `cleanup.sh` 를 맨 끝에만 두면
그 스크립트가 있어도 누수는 그대로다 — 문제는 도구가 아니라 **시점**이었다.

⚠ 병렬이 아니어도 절은 만들어라. 「단독 — 항목 넷이 한 패키지의 같은 파일 셋을 고친다」처럼
**이유를 적은 한 줄**이면 된다. 절이 없으면 `/go` 가 「안 정했다」와 「단독으로 정했다」를 가르지
못한다(`go-precheck.sh` 가 그 부재를 알린다).

마지막에 계획을 요약해서 보여주고, **바로 다음에 칠 명령을 그대로 출력하고 멈춰라**:

    승인하시려면:  /go P0~P4          ← 실제 단계 번호로

범위를 줄여 승인할 수 있는 지점이 있으면 그 선택지도 한 줄로 같이 보여라
(예: `/go P0~P2` — Helm·발급도구 빼고. 「라이선스를 입력하면 메뉴가 켜진다」까지는 완성).
사용자가 복사 한 번으로 착수할 수 있어야 한다.
