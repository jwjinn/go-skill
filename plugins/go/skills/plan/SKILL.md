# /go:plan — 계획을 만들고 다듬는다

이 명령은 **읽기와 계획·목업 파일 쓰기만** 한다. 실행은 사람이 `/go:start` 를 쳐야 시작된다 — 그 명령은 Claude 가
스스로 부를 수 없게 막혀 있고, 그것이 「승인은 사람만 한다」의 구조다.

## 0. 인자

- `$ARGUMENTS` 가 요청 문장이면 그것이 **원 요청**이다. 그대로 인용해 초안 머리에 둔다(바꿔 말하지 마라).
- 기존 초안 디렉토리 이름(`20261012-xxx`)이면 그 초안을 열고 4단계부터 이어간다.
- 비어 있으면 `.claude/plans/*/` 에서 `plan.md` 없이 `draft.md` 만 있는 것(보류한 초안)을 찾는다. 하나면 그것을,
  여럿이면 디렉토리 이름과 원 요청 한 줄씩 보여 주고 묻는다. 없으면 「무엇을 만들까요」 한 줄만 묻고 끝낸다.
  다시 열 때는 「실측」 절의 파일:줄 이 아직 맞는지 먼저 확인하고, 어긋나면 고쳐서 보여 준다.

## 1. 실측 (읽기만 한다)

계획을 쓰기 전에 그 자리의 코드를 연다. CLAUDE.md 에 「증상 → 슬라이스 → 진입 파일」 표가 있으면 거기서
출발한다. 이미 있는 것(헬퍼·부품·검사기)을 먼저 찾는다 — 있는데 안 쓰는 것이 가장 흔한 낭비다.
영역이 여럿이라 한 세션이 다 읽으면 문맥이 넘칠 때만 `Explore` 에이전트에 영역별로 나눠 맡긴다(요약만 돌려받는다).
한두 파일이면 직접 읽는다. 이 단계에서 파일을 고치지 마라.

## 2. 초안을 쓴다 — `.claude/plans/<YYYYMMDD-slug>/draft.md`

`Write` 도구로 쓴다(Bash 재지향으로 쓰지 마라 — plan-gate 는 Write/Edit 흔적으로 「이 세션의 계획」을 가른다).
**초안은 `draft.md` 다.** plan-gate 는 `plan.md` 만 보므로, 초안을 고치는 동안에는 턴이 막히지 않는다.

```markdown
# <제목> — <YYYY-MM-DD>

## 목표 계약
- 원 요청: 「<$ARGUMENTS 그대로>」
- 수용 기준: <끝났다고 볼 수 있는 관찰 가능한 조건 1~3개>
- 범위 밖: <하지 않을 것 — 비워 두지 마라>

## 실측
<1단계에서 본 것. 파일:줄 로>

## 단계
- [ ] <단계> — 검증: <무엇을 돌려 확인하나>
- [ ] …
- [ ] 리뷰·검사·PR — /go:review

## 병렬 배치
<배치가 하나면 「없음(순차)」. 둘 이상이면 배치마다:>
- 배치 A「<이름>」 — 단계: <위 단계 중 어느 것> · 파일 집합: <경로들> · 공유 자원: <DB·포트·픽스처 중 건드리는 것, 없으면 없음> · 완료 조건: <검증 명령>
- 배치 B「<이름>」 — …
- 합치기(/go:start 세션): <머지 순서 · 합친 뒤 돌릴 게이트>

## 결정 필요(승인 전)
- <사용자만 답할 수 있는 갈림길. 없으면 「없음」>

## 자원 회수
<임시 파일·브랜치·워크트리 중 끝나면 치울 것. 없으면 「없음」>
```

단계는 **검증을 붙여서** 쓴다. 테스트를 만들 단계에는 「보호를 깨서 붉어지는 것을 본다」를 넣는다(대조군 없는
테스트는 근거가 아니다).

**병렬 배치는 초안에서 정한다.** 서로 파일 집합이 겹치지 않고 공유 자원을 같이 건드리지 않는 단계 묶음만 배치로
나눈다. 파일 집합이 한 경로라도 겹치면 배치가 아니라 순차다 — 초안 단계에서 합쳐라. 워커는 사람에게 묻지 못하므로,
배치가 둘 이상이면 **결정 필요 절을 더 꼼꼼히** 채운다(워커가 갈림길을 만나면 멈춰 보고하는 것이 전부다).

## 2-b. 화면 목업 — 화면을 바꾸는 계획이면

사용자가 보는 화면의 구성·배치·상호작용이 바뀌는 단계가 있으면, **그 화면마다 목업 4안(A~D)** 을 만들어 사용자가
고르게 한다. 고른 안이 그 화면의 명세다. `/go:start` 는 그 안을 그대로 구현한다.

- 대상: 새 화면 · 화면 개편 · 기능 추가로 화면이 바뀌는 경우. 대상이 아닌 것: 의도한 동작으로 되돌리는 버그 수정,
  화면이 그대로인 내부 수정. 애매하면 「결정 필요」에 「<화면> 은 목업 없이 갈까요」를 넣는다. 사용자가 「목업 없이」라고
  하면 만들지 않는다.
- 저장소의 목업 규약을 먼저 찾는다. CLAUDE.md 와 `.claude/rules/*.md` 에서 「목업」을 검색해 가리키는 문서를 연다.
  규약이 자리·형식·검사기를 정한다. 규약이 없으면 `.claude/plans/<slug>/mockups/<화면>/` 에 `A.html`~`D.html` 과
  `index.html` 을 둔다.
- 목업은 화면마다 `Agent`(general-purpose) 하나가 만든다. 화면이 여럿이면 같은 응답 안에서 전부 띄운다(목업 HTML 이
  이 세션의 문맥을 채우지 않게 하려는 것이다). 프롬프트에 넣을 것:
  > 화면 「<이름>」의 목업 4안(A~D)을 <출력 디렉토리> 에 만들어라. 진입 경로: <메뉴·URL>. 지금 그 화면에 있는 기능과
  > 자리: <실측에서 본 기능 목록 · 파일:줄>. 이번 계획에서 바뀌는 것: <단계 요지>. 먼저 <규약 문서> 와 <디자인 문서> 를
  > 읽고 따르라(없으면 생략). 네 안은 배치나 흐름의 방향이 서로 달라야 한다. 색이나 간격만 바꾼 변형은 다른 안이 아니다.
  > 값을 지어내지 마라. `index.html` 에 네 안을 나란히 놓고 안마다 무엇이 다른지 한 줄로 적어라. 저장소에 목업 검사기가
  > 있으면 돌려서 통과시켜라. 마지막 메시지에 파일 경로와 안마다 한 줄 요약을 적어라.
- 초안에 반영한다. 「결정 필요」에 화면마다 한 줄을 넣는다:
  `- [ ] [목업] <화면> — A~D 중 · 보기: <index.html 경로>`.
  고르면 `- [x] [목업] <화면> — 답: B (<B 파일 경로>)` 로 닫고, 그 화면을 고치는 단계 끝에 `— 명세: <B 파일 경로>` 를 붙인다.
  「B 에 C 의 표」처럼 섞은 답은 그대로 적고 명세에 두 경로와 무엇을 어디서 가져오는지를 적는다.

## 3. 결정을 먼저 닫는다

「결정 필요」에 항목이 있으면 `AskUserQuestion` 으로 **한 자리에서 전부** 묻는다(도구가 없는 세션이면 질문을
번호로 출력하고 턴을 끝낸다). 답이 본문을 바꾸면 초안을 다시 쓴다.
목업 선택은 화면마다 질문 하나로 묻는다. 선택지는 A~D 이고 설명에 안마다 한 줄 요약을 넣는다(한 번에 넷까지 물을 수
있으므로, 화면이 넷을 넘으면 나눠 묻는다). 묻기 전에 `index.html` 경로를 보여 주고, macOS 면 `open` 으로 연다.

## 4. 다듬는다 — 협의 루프

초안을 보여 주고 이 한 줄로 끝낸다:

> 고칠 것이 있으면 그냥 말해 주세요. 이대로 실행하려면 **`/go:start`**, 나중에 하려면 그대로 두면 됩니다(초안은 남습니다).

그 뒤 사용자의 모든 메시지는 **고치는 말**이다. 형식을 요구하지 마라:
- 「이것도 추가해」「그 화면도 같이」 → 실측을 그만큼 더 하고 단계·파일 집합·병렬 배치·수용 기준을 늘린다. 추가된 일이
  기존 배치와 파일 집합이 안 겹치면 새 배치로, 겹치면 같은 배치에 넣는다.
- 「3단계 빼」「그건 다음에」 → 줄을 지우고 「범위 밖」 절에 옮긴다.
- 「목업 다시」「B 에서 표만 바꿔」 → 그 화면의 목업만 `Agent` 로 다시 만들고, 그 화면의 목업 결정 줄을 다시 연다.
  새로 화면이 추가되면 그 화면의 목업 4안도 만든다(2-b).
- 「왜 이렇게 나눴어?」 같은 질문 → 답하고, 답이 계획을 바꾸면 고친다.
- 새 요청이 원 요청과 무관하게 커지면(다른 기능·다른 화면 묶음) 「따로 `/go:plan` 으로 나눌까요, 이 계획에 넣을까요」를 묻는다.
고칠 때마다 `draft.md` 를 `Edit` 로 갱신하고, **바뀐 절만** 보여 준 뒤 현재 단계 체크리스트 전체와 위 한 줄을 다시 붙인다
(매번 전문을 다시 찍지 마라). 원 요청 줄은 바꾸지 않고, 추가된 요청은 그 아래 「추가 요청(날짜)」 줄로 쌓는다.

⛔ 사용자가 「시작」「진행해」「좋아 해줘」처럼 **말로** 실행을 청해도 구현하지 마라. 「실행은 `/go:start` 를 쳐 주세요」
한 줄로 답한다. `plan.md` 를 쓰는 것도, 코드를 고치는 것도 `/go:start` 안에서만 일어난다.

## 하지 마라

- 코드를 고치지 마라. 이 명령이 쓰는 파일은 `draft.md` 와 목업 파일뿐이다.
- `plan.md` 를 쓰지 마라. 그것은 승인이고, 승인은 `/go:start` 다.
